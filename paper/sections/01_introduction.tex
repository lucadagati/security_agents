\section{Introduction}
\label{sec:intro}

\IEEEPARstart{S}{ecurity} evaluations of autonomous AI agents are
usually static. A model is red-teamed once, a defender is scored against
a fixed script, or both sides reset after every episode. That setting
measures isolated capability, not the dynamics that appear when
attackers and defenders \emph{both} learn from prior encounters. Yet
modern agent stacks already support persistent memory, tool use and
multi-agent coordination~\cite{park2023generative,wu2023autogen,xi2023rise,shinn2023reflexion}.
Once deployed, they will not face a frozen opponent; they will face an
adversary (or a defensive stack) that adapts. Red-teaming reports that
score a model on a fixed prompt suite therefore measure a snapshot, not
the trajectory that arises when the defender patches, rotates credentials,
or deploys deception after the first probe.

Recent agentic-security work has documented prompt injection, tool
misuse, memory poisoning and collusion~\cite{greshake2023not,debenedetti2024agentdojo,zhan2024injecagent,chen2024agentpoison,abdelnabi2024cooperation}.
These results are essential, but they rarely let \emph{both} sides
adapt over a long horizon. The question we study is therefore
complementary to one-shot robustness testing:

\begin{quote}
\textit{How does cybersecurity evolve when attackers and defenders are
autonomous learning agents rather than static programs?}
\end{quote}

We answer it in two steps. First, we propose a formal view of security
as a function of capabilities, goals, interaction, adaptation and
history rather than as a property of an isolated agent:
\begin{equation}
  \mathrm{Security}
  \;=\;
  f\!\left(\mathcal{C},\, G,\, \mathcal{I},\, \alpha,\, H\right),
  \label{eq:security-fn}
\end{equation}
where $\mathcal{C}$ denotes capabilities, $G$ objectives, $\mathcal{I}$
the interaction structure, $\alpha$ the adaptation regime, and $H$ the
accumulated experience. Second, we build an experimental platform and
use it to measure whether co-evolutionary phenomena appear already in
the smallest scientifically meaningful setting: one attacker and one
defender, repeated episodes, controlled adaptation levels.

Our contributions are fivefold.
\begin{enumerate}
\item A problem formulation that separates capability, objective and
strategy, so that unexpected behaviour can be attributed to interaction
rather than to newly granted tools (Section~\ref{sec:problem}).
\item A co-evolutionary agent framework with three adaptation levels,
an interaction graph, trajectory logging and operational emergence
criteria (Section~\ref{sec:framework}).
\item A dual-backend cyber environment (seedable simulator and optional
Kubernetes range) with partial observability and structured tools rather
than unconstrained code execution (Section~\ref{sec:environment}).
\item Metrics, a two-study protocol and analysis pipeline (CEP, dynamics
class, emergence tagging; Section~\ref{sec:method}).
\item Empirical evidence that co-evolutionary phenomena appear at one-versus-one
under stated adaptation regimes (Section~\ref{sec:results}).
\end{enumerate}

The paper is organised as follows. Section~\ref{sec:related} situates
the work. Sections~\ref{sec:problem}--\ref{sec:environment} present the
formal setting, framework and environment. Section~\ref{sec:method}
defines metrics, policies and protocol. Section~\ref{sec:results}
reports findings. Sections~\ref{sec:discussion}--\ref{sec:conclusion}
discuss implications and conclude.
