\section{Experimental Environment}
\label{sec:environment}

The environment models a layered enterprise network
(Fig.~\ref{fig:network}): an external attacker, a gateway, service hosts
and a protected data store. Hosts carry sampled vulnerabilities; service
hosts may hold credentials that unlock deeper targets. Defenders can raise
monitoring, investigate, isolate hosts, rotate credentials, block ingress
or deploy decoys.

\input{figures/network}

Agents act only through a fixed catalogue of structured offensive and
defensive tools (reconnaissance through data exfiltration on the attack
side; monitoring, containment and deception on the defence side). Tools
are validated against JSON schemas; the kill-chain ordering is an
environment property, not a scripted policy. A static heuristic may follow
that order linearly, whereas adaptive or language-model agents may wait,
diversify or communicate. The full catalogue is documented in the
open-source release (Appendix~\ref{app:repro}).

Attackers initially know nothing; reconnaissance and probing reveal
structure. Defenders observe suspicion only where they monitor. Noisy
actions raise suspicion; an automatic detector fires with probability
$1-e^{-\lambda \sigma}$, after which suspicion and monitoring decay.
Inserting low-noise pauses after high-noise actions (stealth pacing) is
therefore a meaningful strategy discovered from the physics of detection,
not from an explicit objective to ``wait.''

The same interface is implemented by an in-memory simulator (used for the
results below) and by an optional Kubernetes backend that mirrors selected
defensive actions onto a sandbox cluster~\cite{standen2021cyborg,microsoft2021cyberbattlesim}.
Every step is logged as a trajectory record (observation, action,
outcome, rationale, strategy label, memory update) keyed by experiment
configuration, seed and repository revision~\cite{park2023generative}.
