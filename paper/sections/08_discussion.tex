\section{Discussion}
\label{sec:discussion}

Co-evolutionary security phenomena appear already in one-versus-one adaptive
cyber games and are visible in process metrics (CEP, dynamics class,
emergence tags), not only in ASR. Language-model agents add a capability gap
that must be separated from adaptation effects through the hybrid protocol
of Section~\ref{sec:method-policies}.

\paragraph{Implications for evaluation.}
Evaluations that freeze the opponent will mis-state risk: a defender that
``passes'' against a static red team may fail against an adversary that
remembers prior detections and adjusts stealth. Reports should disclose
adaptation level and memory regime on \emph{both} sides, plus control
structure when LLMs participate (schemas, hybrid gates, reflection format),
not only model identity or tool inventory.

\paragraph{Emergence and monitoring.}
Unexpected tool sequences need not denote new vulnerability classes. Delayed
attack here is strategic use of an existing low-noise action under the
detection law of Section~\ref{sec:environment}. Monitoring should track
strategy signatures and co-evolutionary pressure alongside atomic indicators.

\paragraph{Limitations.}
The simulator's detection law, coarse observability and three-host topology
limit external validity. Hybrid success attributes jointly to model and gate;
supplementary LLM cells use fewer seeds. Population experiments and paired ESR
runs (H3, H6) may change qualitative conclusions; the Kubernetes backend has
not been evaluated on a live range.

\paragraph{Future work.}
The E3--E8 matrix extends the same protocol to communication, graph topology
and larger populations. Paired ESR runs will test H3; Kubernetes validation
will probe infrastructure realism. Evaluation reports could state the
adaptation ladder cell and observed dynamics class as a \emph{regime
declaration} rather than a single pass/fail bit.
